## One-paragraph state

V5.2 is past pure design: a **minimal, experimental generic payload is implemented and published**, covering project knowledge lifecycle, first-use initialization, opt-in delivery workflows, a thin context slice, and two bounded governance/safety slices. It has not reached a product release. Most portfolio candidates remain framed, candidate, parked, or only partially implemented, and broad memory benefit, general context policy, and full governance remain unproven.

## Implemented and validated

Published in the clean payload at `1f26fbe`:

- **C02 bounded slice** — scoped retrieval, inactive candidate staging, explicit promotion/rejection, correction/supersession, explicit retrieval outcomes (`applicable` / `no match` / `filtered` / `unavailable`).
- **C11 first-use initialization** — scope/profile/policy/index creation behind one complete preview, explicit approval, fresh-session `.pi` wiring, existing state preserved.
- **Delivery workflows** — opt-in `/plan`, `/implement`, `/premortem`; transient plan checkpoint; separate checkpoint disposition; standard implementation logs.
- **C03 thin slice** — prompt-driven context guidance and content-free context metrics with canonical source/outcome vocabulary.
- **C04 first slice** — path-based sensitive-file protection (`.env`, `.env.*`, `frontend/.env`, credentials/keys) with lexical shell-segment handling, plus semantic authorization-fidelity, blocker, and fail-safe rules.
- **C04 action-scope slice** — checkpoint-derived exact write/shell scope during `/implement`, fail-closed scope verification, exact approved validation commands, and a narrow checkpoint-deletion exception.
- **C11 reviewed refresh** — payload revision plus sha256 manifest recorded at initialization; a previewed refresh applies only payload-owned files, stops on local divergence, and verifies a no-op afterwards.
- **Knowledge subject guard** — candidates whose title or claim describes AgenticLab's own installation or workflow are rejected; only evidence may quote installation paths.
- **Knowledge-path hardening** — staging no longer rejects candidates that merely quote `.gitignore`; checkpoint removal and read-only knowledge access work behind a normal `cd … &&` prefix while mixed mutation chains stay blocked.

Delivery and knowledge evidence, all measured and preregistered:

- `ALPHA-DELIVERY-001` — five bounded checkers, 148 tests, $0.175, four frictions found and three fixed.
- `ALPHA-KNOWLEDGE-TRANSFER-001` — retrieval fired but formatting rules were not applied (cited score unreproducible, flagged).
- `ALPHA-KNOWLEDGE-APPLICATION-001` — a worked example transferred what prose did not, twice, 7/7.
- `ALPHA-KNOWLEDGE-EXAMPLE-ISOLATION-001` — identical verbose prose scored 5/7 without the example and 7/7 with it.

See `evaluation/plans/` and `evaluation/results/`. Measurement is reproducible from `AgenticLab-tools` (64 tests); session metrics and rubric scoring replace hand-grading.

Validation evidence: 13/13 adapter regression tests and live Pi probes in archived exp5; fresh initialization, sensitive-file probes, authorization-fidelity probe, and `/plan` → `/implement` validation in archived exp6; 16/16 external action-scope tests plus live Pi probes and a real `/plan` → `/implement` run in disposable exp7; four published-payload PBIs plus 8/8 friction tests and live fix confirmation in disposable exp8.

Knowledge reads now require a verb that cannot write: `sed`, `awk`, output redirection, and `find` action flags (`-delete`, `-exec*`, `-fprint*`) are blocked on knowledge paths, while prefixed reads and name-only `find` stay allowed.
